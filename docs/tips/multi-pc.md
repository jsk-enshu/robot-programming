# 複数PCの接続設定

班員のPCを複数台使うことで各処理を分散しながらJedyを動かすこともできる．
Jedyがネットワークに接続されている状態で，それ以外の演習PC(遠隔PC)から指令値を送りセンサの表示を見るような構成になる．
本章では，そのような構成のための複数PC間でのROSのネットワーク通信方法について説明する．

Jedy
PCにsshして作業する際に，ロボットPCにsshしている複数のPCでプログラムを実行しているbashターミナルの画面を共有できた方が便利である．
そのためにtmuxやscreen，byobuという便利なコマンド用意されている．
byobuコマンドを付録で紹介しているので，ぜひ活用してみてほしい．

### 複数のPCでROSの通信を行う際の時刻同期

複数PCを使うROSのネットワークでは，
複数PC間で時刻の同期を行うことが重要である．
topicなどのデータは，ほぼタイムスタンプという
時刻のデータを付加して送受信している．
以下のようにして時刻合わせの設定を行う．
**この作業は必ずjedy-wifi-5gに接続して行うこと．**

<div class="screen">

``` bash
$ sudo ntpdate ntp.nict.jp
#「コマンドが見つかりません」となる場合はsudo apt install ntpdateによりntpdateをインストールする．
```

</div>

### ワイヤレスネットワーク接続

複数PC間での通信は，
それぞれのPCを同一のネットワークに接続することで行う．
本演習ではjedy-wifi-5gを利用する．

なおROSでの通信はTCP/IPを利用しており，
IP等解決できない場合は通信ができない． 例えば，(1)
roscore/roslaunchを**jedy-wifi-5g以外**のネットワークに接続した状態で起動したあと，
(2) このプロセスを残したままjedy-wifi-5gに切り替え， (3) rostopic
echoなどでROSノードにアクセスしようとする，
などとするとアクセスできない． これは，wifiネットワーク切り替え時に
IPや通信可能なネットワークが変わってしまうためである．
そのため，ネットワークが変わるときには必ずroscore/roslaunchを
一度シャットダウンし，ROS_MASTER_URIなどの再設定・確認を行う．

### ROS_MASTER_URI, ROS_IP, ROS_HOSTNAMEの設定

ROSの通信を行うには， ROS_MASTER_URI (どこをマスタにするかの設定)，
ROS_IP, ROS_HOSTNAME (マスタに対する自分の設定)
という環境変数を設定する必要がある．

これらの環境変数は手動で設定してもよいが(例: export ROS_IP=10.0.0.1)，
本演習では，jsk_toolsパッケージ[^12]
で提供される便利なbash関数(rossetlocal, rossetip,
rossetmaster)を利用する．

- rossetlocal : ROS_MASTER_URIをlocalhostに設定する．

- rossetip : ROS_IPとROS_HOSTNAMEを現在のIPアドレスに設定する．

- rossetmaster :
  ROS_MASTER_URIを引数で指定されたアドレスに設定する．自分自身以外をマスタにする場合に利用する．

演習では，ロボットPC(TrutlebotのUSBケーブルを接続するPC)をマスタとし，遠隔PCはそれに接続する．
ロボットPCでは，自分がマスタになるように，以下を実行する．

<div class="screen">

``` bash
$ rossetlocal
$ rossetip
```

</div>

遠隔PCでは，ロボットPCをマスタにする必要がある． そのためにロボットPCで

<div class="screen">

``` bash
$ ifconfig
```

</div>

もしくは

<div class="screen">

``` bash
$ ip a
```

</div>

を実行して現在のロボットPCのIPアドレスを調べてから(例えばロボットPCのIPアドレスが192.168.0.100とすると)，
遠隔PCで

<div class="screen">

``` bash
$ rossetmaster 192.168.0.100
$ rossetip
```

</div>

を実行する．

環境変数の確認は，以下のようにして行う．

<div class="screen">

``` bash
$ echo $ROS_MASTER_URI
http://192.168.0.100:11311
$ echo $ROS_IP
192.168.0.101
```

</div>

このROS_MASTER_URI，ROS_IPなどの環境変数は，ターミナルごと設定する必要がある．
つまり，上記のような設定が必要な場合は，**新しいターミナルを上げるごとに毎回実行**しなければならない．
また，**ネットワークを切り替えた場合にも再度設定が必要**である．

ロボットPCと遠隔PCで起動するプログラムが分かれると，
それぞれの計算機の処理する計算負荷が低くなる．
一方で，PC間でのネットワークを介した通信をしなければならず，
特に今回のように無線のネットワークを介する場合は，
画像データなど大量のデータをネットワークで通信することは難しい．
実際に遠隔PC，ロボットPCと複数PCでロボットを動かす場合，
**計算負荷の分散できるメリット・
無線ネットワーク上で通信を行うデメリット等の
トレードオフなどを考えながら
どのノードをどのPCで起動すべきか判断し進める必要がある．**

ネットワークの切り替え・複数PC利用時における注意をまとめておく．

- ROSで通信する複数のPCは同一のネットワークに接続する必要がある．

- wifiネットワーク切り替え時に
  IPや通信可能なネットワークが変わってしまうため，
  ネットワークが変わるときには必ずroscore/roslaunchを
  一度シャットダウンし，ROS_IPなどの再設定・確認を行う．
  単純には，古いネットワークのターミナルごと落として新しいターミナルを起動する．

- ファイアウォールが有効になっていると通信ができないことがある． sudo
  ufw statusで確認してファイアウォールが有効化されている場合は，sudo ufw
  disableを実行しPCを再起動してファイアウォールを無効化する．

- (次回以降で)EusLispで\*ri\*作成時に Kinematics Simulatorとかかれた
  黒背景のEusLispのビューワ(irtviewer)が現れた場合，
  実機に接続できていないため，実機までのnetwork確認や
  実機側のlaunchファイルなど(jedy_bringup.launch.pyなど)に
  問題ないか確認すること．
